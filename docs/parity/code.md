## Deliberate integration changes

Pi ExtensionAPI, TUI renderers, provider authentication, remote context, opaque results and voice are excluded by the accepted Durable-native scope. Context-window control belongs to the separate Context component and uses generic native-only tool registration metadata. TOML custom commands are loaded as ordinary registrations using explicit trust and namespace-bound capabilities. Code and Notebook each expose the same factories from one internal implementation, so Notebook does not depend on Code. There is no component-specific dispatch bridge. Native host execution remains a runtime dependency, not an embedded Rust shell tool bundle.

JavaScript receives the shared ordinary-tool result projection: meaningful `details` with result content preserved, otherwise parsed JSON text or raw text. Image content adds an `image_url`. Errors throw. The Durable result itself is retained in audit records. This replaces source-specific Pi adapters without dropping their content.

Custom commands preserve their explicit string result even when stdout contains JSON. Their ordinary registration records that string as details matching its text content, so generic projection need not guess its type. Pure preparation accepts the original scalar string before ordinary object-schema validation.

Source text-only rendering of shell command metadata and Pi-specific accidental `wait` recovery for shell session IDs are not replicated as cross-component bridges. Shell commands retain their structured result and their session ID. The prompt distinguishes shell `write_stdin` from cell `wait`. Display-only renderers are outside this headless package.

V8 session `store` data, live tool promises, and native cells are process-local. They cannot be restored after restart. The coordinator marks an uncertain cell interrupted rather than replaying it. PTY restart behavior is recorded in the shell parity document.

A failed native host is not automatically replaced with an empty session. Previous partial output and an uncertain-outcome diagnostic are retained. Recreating the component is an explicit recovery boundary.

The driver retains at most one bounded native output batch while awaiting delivery acknowledgement. It then resumes native observation. This preserves source per-observation output budgets without accumulating an unbounded backlog or discarding later output before a model-visible wait consumes it. Native code itself continues independently until completion or cancellation.

Earlier port measurements recorded 771 UTF-8 bytes of emitted `exec` and `wait` schemas including the Lark grammar. Discovery guidance now also explains no-argument help. Each promoted contract adds only its usage line or explicit help-backed description. Other registrations stay in runtime discovery instead of provider tool schemas. The actual Durable integration test checks the projected provider offer.
