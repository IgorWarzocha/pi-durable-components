# Context management

The native policy is persistent notes plus retained history, with foreign reads confined to matching visibility groups. Writes belong to the caller. Tool rollover requires fresh checkpoint notes and continues the same native input. Host rollover requests a completed checkpoint before starting a clean window. Automatic idle rollover is host opt-in and uses already-fresh notes without requesting a checkpoint. Compaction is reserved for emergency overflow.

## Whole-package corrections

The audit against read-only Pi Stuff `12c4357b2c401fe9be8c6c82d2ae252c0f986937` found that local retained history is a genuine equivalent for linear window cuts, but not proof of Tree archive indexing or Remote family discovery. Source `tree-archive.ts`, `local-history.ts`, `history-notes.ts` and `sharing-service.ts` establish those retrieval and namespace workflows. Different storage and transport do not justify dropping them.

`archiveHistory: true` opts into native retained-fork discovery through public conversation ancestry and entries. Existing window and item IDs remain valid. Additional branch windows receive opaque `archive:` IDs. Searches prioritise actual native compaction summaries after validating their retained head references. Returned IDs support exact bounded raw-entry and summary reads. Recovery guidance supplies summary and recent-user IDs without injecting their contents. Notes-only rollover invents no summary. Scans observe caller cancellation and fail explicitly beyond 10,000 conversation records or 50,000 archive entry reads. No second transcript store, persisted shadow catalog or Pi archive manifest is introduced.

`remote: ContextRemoteCatalog` opts into a host-owned stable family and agent catalogue. Its `catalog(caller, context)` returns `familyId`, `currentAgentName` and agent-name/conversation pairs. The current name must resolve to the caller. Ordinary Notes and History help lists only visible identities. Existing actions accept `agent_name` or a numeric target, constrained to that configured family and the existing visibility group. Archive branches must satisfy both constraints too. Writes remain caller-owned. Invalid configuration or resolver failure is an error, never permission to fall back locally. This preserves the account/family namespace workflow through native conversations, not the source's Codex remote backend. A consuming app must explicitly supply the catalogue before claiming that workflow.

## Storage and lifecycle

Ordinary tools implement the source action names, case-sensitive substring searches, filters, bounded previews and offset retrieval. History reads fork-aware Durable entries in pages, including entries behind the active head. Item IDs are stored entry IDs. Context windows have UUIDs; a host-created peer without Context state uses `conversation:<id>` until initialized. Reads do not initialize the target's window or notes. Image bodies are omitted from history text. Notes use rewindable per-path document families with a bounded catalog. Body, catalog, freshness and the original write receipt commit together. Replayed append results cannot append twice or refresh old freshness.

The component uses the official Durable 1.0.2 storage and public task APIs. `management.submit` durably saves the original input before admission. Each input retains its content, attachments and native busy policy. Stable request IDs deduplicate admission and internal checkpoint submissions. A FIFO gate releases as soon as an input reaches native admission, rather than serializing complete model runs and breaking steer behavior.

Settlement observation and the managed task's outcome commit together. The stored timestamp is observation time, not an invented native completion timestamp. A crash before this commit produces a later observation after recovery, delaying the idle cut. The configured idle deadline also requires the same latest input identity, successful completion, fresh notes and no live foreground work. Older persisted settlements without completion evidence cannot authorize automatic cuts. If the conditions change before rotation, the transition returns `status: "skipped"` and admission continues without cutting the head.

Host and idle rollover wait for the actual native submission and foreground cells, then commit the head cut and new window after an idle recheck. Tool rollover instead uses the paused native generation's `afterTools` boundary, described below. Initialization appends a non-head marker and never cuts an existing transcript. The old entries, conversation ID, notes and live execution runtimes remain available. Native overflow compaction changes the active model context without changing the logical window UUID.

Failed host checkpoints retain original input for an explicit retry or a new user message. Cancelled checkpoints cancel held messages instead. Cancellation intent commits before the rollover claim and admission gate are released. The managed reader retains support for previously persisted tool-continuation receipts. New tool rollovers no longer create that second submission chain.

Installing the extension alone cannot intercept every host input. Direct `Conversation.submit` calls, including agent dispatch and notification inputs, bypass idle admission. Consumers must use the managed entry point for that guarantee. Manual host rollover is `management.newContext`, not an interception of `Conversation.compact`: Durable's compaction hook runs only after native range selection. Normal threshold and manual compactions are declined there; overflow is allowed.

## Tool projection and usage

`new_context` is an ordinary registration carrying the generic `executionHints.nativeOnly` policy. Code and Notebook resolve selected, wrapped registrations from their explicitly bound Harness. Discovery omits native-only tools, nested dispatch rejects them, and provider projection preserves them. Mixed native rounds reject. A call without fresh notes returns `checkpoint_required` and asks the model to save notes and retry within the current input, rather than ending it to launch a synthetic checkpoint input.

With fresh notes, a generation-scoped receipt requests the cut. `afterTools` verifies the exact live generation, its sole completed tool, no queued inbox items, no competing foreground task, the original window and fresh notes. The window marker, chronological continuation instruction and replay receipt commit together. Durable then advances its existing run normally. There is no terminate control, replacement submission or Agents-specific completion bridge. A failed safety check appends a visible skipped-rollover message without cutting. Cancellation after a cut remains native cancellation, not permission to replay or restart work.

The usage meter combines the latest applicable assistant counters with the public Pi AI tail estimator. It uses entry ordering, not assistant timestamps. Unknown budgets remain unknown. Compaction invalidates usage from the retired prefix. The 85% and 90% reminders are advisory and deduplicated by logical window, with fresh-note suppression. Prompt bootstrap loads recent note metadata only and points to listing or searching additional notes. Guidance keeps task checkpoints at stable paths, with reusable findings and deferred ideas in linked topic notes.

At extraction, an equivalent first-turn capture with the same Harness, faux model, clock and `Hello` input measured 52 JSON UTF-8 bytes without the extension and 3,082 with it. The four emitted tool declarations occupied 2,565 bytes. The checkpoint-guidance refresh changes the section size. These historical wire-size measurements are not current token counts. The section still includes no note bodies or archived transcript.
