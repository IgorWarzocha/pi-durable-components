# Context management

The native policy is persistent notes plus retained history, with foreign reads confined to matching visibility groups. Writes belong to the caller. Tool rollover requires fresh checkpoint notes and continues the same native input. Host rollover requests a completed checkpoint before starting a clean window. Automatic idle rollover is host opt-in and uses already-fresh notes without requesting a checkpoint. Compaction is reserved for emergency overflow.

## Storage and lifecycle

Ordinary tools implement the source action names, case-sensitive substring searches, filters, bounded previews and offset retrieval. History reads fork-aware Durable entries in pages, including entries behind the active head. Item IDs are stored entry IDs. Context windows have UUIDs; a host-created peer without Context state uses `conversation:<id>` until initialized. Reads do not initialize the target's window or notes. Image bodies are omitted from history text. Notes use rewindable per-path document families and a metadata catalogue. Body, catalog, freshness and the original write receipt commit together. Replayed append results cannot append twice or refresh old freshness.

The component uses the official Durable 1.0.2 storage and public task APIs. `management.submit` durably saves the original input before admission. Each input retains its content, attachments and native busy policy. Stable request IDs deduplicate admission and internal checkpoint submissions. A FIFO gate releases as soon as an input reaches native admission, rather than serializing complete model runs and breaking steer behavior.

Settlement observation and the managed task's outcome commit together. The stored timestamp is observation time, not an invented native completion timestamp. A crash before this commit produces a later observation after recovery, delaying the idle cut. The configured idle deadline also requires the same latest input identity, successful completion, fresh notes and no live foreground work. Older persisted settlements without completion evidence cannot authorize automatic cuts. If the conditions change before rotation, the transition returns `status: "skipped"` and admission continues without cutting the head.

Host and idle rollover wait for the actual native submission and foreground cells, then commit the head cut and new window after an idle recheck. Tool rollover instead uses the paused native generation's `afterTools` boundary, described below. Initialization appends a non-head marker and never cuts an existing transcript. The old entries, conversation ID, notes and live execution runtimes remain available. Native overflow compaction changes the active model context without changing the logical window UUID.

Failed host checkpoints retain original input for an explicit retry or a new user message. Cancelled checkpoints cancel held messages instead. Cancellation intent commits before the rollover claim and admission gate are released. The managed reader retains support for previously persisted tool-continuation receipts. New tool rollovers no longer create that second submission chain.

Installing the extension alone cannot intercept every host input. Direct `Conversation.submit` calls, including agent dispatch and notification inputs, bypass idle admission. Consumers must use the managed entry point for that guarantee. Manual host rollover is `management.newContext`, not an interception of `Conversation.compact`: Durable's compaction hook runs only after native range selection. Normal threshold and manual compactions are declined there; overflow is allowed.
